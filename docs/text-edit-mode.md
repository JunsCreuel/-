# 글 수정 모드 사용법

사이트 화면에서 글을 직접 눌러 고치고, 저장하면 1~2분 뒤 실제 사이트에 반영돼요.
방문자에게는 아무것도 보이지 않고, GitHub 토큰이 있는 사람만 쓸 수 있어요.

## 1. 처음 한 번: GitHub 토큰 만들기

1. GitHub에 로그인한 뒤 오른쪽 위 프로필 → **Settings**
2. 왼쪽 맨 아래 **Developer settings** → **Personal access tokens** → **Fine-grained tokens**
3. **Generate new token**
4. 입력할 것
   - **Token name**: `landing-text-edit` (아무 이름)
   - **Expiration**: 90 days 정도 (만료되면 새로 만들면 돼요)
   - **Repository access**: **Only select repositories** → 이 저장소 하나만 선택
   - **Permissions → Repository permissions → Contents**: **Read and write**
5. **Generate token**을 누르고, `github_pat_…`으로 시작하는 토큰을 복사해 두세요. 화면을 벗어나면 다시 볼 수 없어요.

토큰은 비밀번호와 같아요. 다른 사람에게 보내거나 채팅에 붙여넣지 마세요.

## 2. 글 고치기

1. 아래 주소로 들어가요. 끝에 `?edit`가 붙어 있어야 해요.
   - 자이점: `https://junscreuel.github.io/-/#/wellness?edit`
   - 마린시티점: `https://junscreuel.github.io/-/#/wellness/marine?edit`
2. 화면 아래에 뜨는 입력창에 토큰을 붙여넣고 **연결**을 눌러요. 토큰은 이 브라우저에만 저장돼서 다음부터는 자동으로 연결돼요.
3. 점선으로 표시된 글을 눌러 그대로 타이핑해서 고쳐요. 고친 글은 배경이 진하게 바뀌어요.
4. **저장하고 사이트에 반영**을 누르면 끝이에요. 1~2분 뒤 방문자 화면이 바뀌어요.

## 3. 알아둘 점

- **고칠 수 있는 것**: 제목, 문단, 칩, 버튼 안의 글(링크형 버튼), FAQ 질문과 답변 등 화면의 문구
- **고칠 수 없는 것**: 전화번호, 주소, 영업시간, 링크, 사진, 푸터의 사업자 정보, 메뉴 이름. 바꿀 때는 개발 쪽에 요청해 주세요.
- 여러 줄 글은 Enter로 줄바꿈하고, 한 줄짜리 글(버튼, 칩 등)은 Enter가 막혀 있어요.
- 글을 모두 지우거나 원래 문구와 똑같이 되돌리면 "원래 문구"로 돌아가요.
- **수정 취소**: 마지막 저장 이후의 수정을 모두 버려요.
- **끝내기**: 수정 모드를 닫아요. 저장하지 않은 수정이 있으면 한 번 더 물어봐요.
- **토큰 지우기**: 이 브라우저에서 토큰을 지워요. 공용 컴퓨터에서 썼다면 꼭 눌러 주세요.
- 저장 직후 1~2분 동안은 방문자 화면이 이전 글 그대로예요. 수정 모드에서는 항상 최신 저장본이 보여요.
- 숫자나 고정 문구가 여러 곳에 반복되는 경우(예: "첫 방문 50%")는 곳마다 따로 고쳐야 해요.

## 4. 되돌리기

저장할 때마다 `src/pages/wellness/content.json`에 기록이 남아요. 잘못 저장했다면 GitHub에서 이 파일의 **History**를 열어 이전 버전으로 되돌릴 수 있어요.

## 5. 문제가 생기면

| 증상 | 원인 |
|---|---|
| "토큰이 맞지 않아요" | 토큰을 잘못 복사했거나 만료됨 |
| "이 토큰으로는 할 수 없어요" | 토큰의 Contents 권한이 Read and write가 아님 |
| "저장소나 파일을 찾지 못했어요" | 토큰의 저장소 선택에 이 저장소가 없음 |
| "다른 곳에서 먼저 저장된 것 같아요" | 다른 기기에서 먼저 저장함. 새로고침 후 다시 시도 |
| "이 주소에서는 저장할 수 없어요" | 배포된 사이트 주소(`github.io`)가 아닌 곳에서 열었음 |

## 개발 메모

- 화면 글은 `<T k="영역.이름">기본 문구</T>`로 감싸져 있고, 저장된 수정본은 `src/pages/wellness/content.json`의 `texts`에 `키: 글` 형태로만 쌓여요. 기본 문구는 코드에 그대로 있어요.
- **수정본이 코드의 기본 문구보다 우선해요.** 코드에서 같은 문구를 바꿔도, 그 키가 `content.json`에 있으면 화면은 안 바뀌어요. 이럴 땐 `content.json`에서 해당 키를 지우세요.
- 방문자 화면은 빌드에 포함된 `content.json`을 쓰기 때문에 추가 요청도, 깜빡임도 없어요. 대신 저장하면 반영에 배포 시간이 들어요.
- 저장은 브라우저가 GitHub API로 `main`에 `content.json` 한 파일만 직접 커밋해요(커밋 메시지: `content: 랜딩 문구 수정 (N곳)`). 이 커밋이 기존 배포 워크플로를 자동으로 실행해요. 이 파일은 데이터 전용이고, 앱은 잘못된 값(문자열이 아닌 값 등)을 무시해서 빌드를 깨뜨리지 않아요.
- 개발·테스트에서는 `window.__WELLNESS_EDIT_REPO__ = 'owner/repo'`로 저장소를 지정할 수 있어요. 배포 주소에서는 `owner.github.io/저장소/`에서 자동으로 알아내요.
